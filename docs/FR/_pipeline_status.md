- **`processed_messages` residual PII on erasure** — tracked, no decode mechanism built. The
  Meta wamid (message_id PK) embeds the sender's phone in cleartext base64, but the table has no
  `phone_e164` column, so `delete_by_phone` cannot phone-scope it without decoding wamids (real
  scope creep, deliberately NOT built). It is only aged out blindly by `purge_older_than`'s
  `received_at` cutoff. Documented in `PostgresIngestStore.delete_by_phone`'s docstring.

- **🔒 Admin-panel pre-deploy security hardening (from Phase 3.5 security review, 2026-07-30)** —
  five items intentionally NOT fixed in Phase 3.5 because they only bite once the panel is on a
  public Vercel URL (Vercel deliberately not connected yet). MUST be closed before the admin panel
  is exposed / before cutover:
  1. **Login rate-limit backing store** (MEDIUM) — `slowapi` uses in-process `memory://`; on
     serverless it resets per cold start and isn't shared across instances, and `get_remote_address`
     returns the proxy IP → the `5/min` guard on the single `ADMIN_PASSWORD` is weak AND an attacker
     could lock the owner out. Fix = Postgres-backed (or Upstash) attempt store + escalating lockout,
     keyed on Vercel's trusted `x-vercel-forwarded-for`. **Owner decision needed at deploy: (a)
     Supabase-backed lockout [recommended, no new vendor] / (b) Upstash Redis / (c) accept for
     single-admin v1 with a mandatory high-entropy password.**
  2. **Session revocation / logout** (MEDIUM) — token payload is only `<exp>`, signed with
     `APP_MASTER_KEY`; no logout, and invalidating a stolen 12h cookie needs rotating
     `APP_MASTER_KEY` (which would destroy all Fernet-encrypted creds). Fix = separate signing
     secret + `session_epoch` in the payload + `POST /admin/logout`.
  3. **`public_base_url` host pinning** (LOW) — accepts any https host and becomes the Shopify
     webhook callback (`jobs/ensure_subscription`); post-compromise, one admin password redirects
     all order PII. Fix = pin to the deploy host from env / allowlist.
  4. **Audit logging** (INFO) — ✅ CLOSED (2026-08-06, REVIEW — ready for code-reviewer).

     logs, no new infra) at: login success/failure/not_configured, credential_set
     (shopify/whatsapp), provider_set (llm:{provider}), knowledge_set (knowledge:{kind}),
     controls_set, erasure (resource=phone). Logs action/resource-NAME/outcome ONLY — never a
     value (passwords, keys, credential contents, knowledge bodies, or the erased phone).
